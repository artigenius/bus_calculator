# Changellenge >> Бизнес-эффект калькулятор — архив проекта

Этот архив содержит всё необходимое, чтобы продолжить работу над калькулятором
экономического эффекта Changellenge >> из другого аккаунта / сессии Claude, без
необходимости заново разбирать Excel-модель или бренд-гайд с нуля.

## Что это за проект

B2B-калькулятор для отдела продаж/L&D компании Changellenge >>. Используется:
- в клиентских встречах,
- в коммерческих предложениях,
- для защиты бюджета перед HRD/CFO клиента.

Задача калькулятора: по нескольким вводимым параметрам компании (штат, зарплаты,
текучесть и т.д.) мгновенно показать расчётный экономический эффект (в рублях),
затраты и ROI — **для одного из 4 продуктов Changellenge >>**:

1. **Стажировки** (Internships)
2. **Марафон роста / внутренний кейс-чемпионат** (Growth Marathon)
3. **EVP (активация)** — активация ценностного предложения работодателя
4. **Кейс-чемпионаты Changellenge >>** (Case Championships)

## Главное жёсткое требование

Математика калькулятора обязана **точно воспроизводить Excel-модель клиента**.
Если пользователь вводит те же значения, что сейчас стоят в Excel — он должен
получить те же результаты. **Никакие новые формулы или бизнес-эффекты добавлять
нельзя.** Это правило проверялось автоматизированными скриптами (см. `scripts/`)
и должно соблюдаться при любых будущих изменениях.

## Как устроен calculator.html

Один самодостаточный HTML-файл (~870 КБ), без бэкенда и без шагов сборки:
- inline `<style>` с CSS custom properties под фирменные цвета/радиусы;
- `@font-face` для 4 начертаний Factor A, встроенных как base64;
- inline SVG логотип/знак Changellenge;
- JS-объект `PRODUCTS` с четырьмя ключами: `internship`, `growth`, `evp`, `championship`;
- каждый продукт имеет: `inputs` (список полей ввода с группами `main`/`advanced`),
  `compute(v)` (функция расчёта, 1:1 повторяющая формулы Excel), `effectCards`
  (карточки-объяснения "почему это работает"), и данные для блока "Как считается?"
  (Логика / Использованные данные / Результат / Источник — источник берётся из
  комментариев в Excel-файле);
- функции рендера: `renderHome`, `selectProduct`, `renderCalc`, `renderResults`,
  `toggleAdvanced`, `handleInput`, `resetDefaults`, `toggleEffect`, `goHome`;
- форматирование чисел под RU-локаль: `fmtMoney` (→ "141,9 млн ₽"),
  `fmtMoneyFull` (полное значение в рублях), `fmtNum`, `fmtPercent`, `fmtRoi`.

### Ключевые константы (зашиты в код, НЕ редактируются пользователем)

`TAX=1.6` (налоговая надбавка на ФОТ), `AGENCY=0.18` (комиссия рекрутера),
`ADAPT_M=6` (месяцев адаптации), `CONV=0.3` (конверсия стажёр→штат),
`EB_RED=0.143` (Стажировки) / `0.43/3` (EVP — именно точная дробь, не
округлённая — см. "Известные тонкости" ниже), `HIRE_SHARE=0.05` (Стажировки) /
`0.10` (EVP), `TEAM_COST` (5 664 000 — Стажировки; 1 232 000 — Марафон роста),
`HOURS_MONTH=168`, `RD_HOURS=20`, `RD_MULT=1.25`, `AI_SHARE=0.42`,
`AI_SAVE=0.0645`, `EFF_GAIN=0.166` (фиксированный рост эффективности в
Марафоне роста — раньше был полем ввода, стал константой по правке
пользователя), `OVERPAY=0.03`, `EXTRA=0.52`, `TURNOVER_RED_SHARE=0.23`,
`HIRE_RATE=0.22`, `CONTACT_DISCOUNT=0.25`, `REACH_MULT=50`.

### Известные тонкости / зафиксированные правки

1. **EVP округление**: `EB_RED` для EVP должен быть `0.43/3` (точная дробь),
   а не `0.1433` (округлённое число) — иначе результат расходится с Excel на
   ~2 900 ₽. Всегда используйте точные дроби, если формула в Excel их использует.
2. **"Ожидаемый рост эффективности участников"** (Марафон роста) — это
   ФИКСИРОВАННОЕ значение модели (16,6%), НЕ поле ввода. Пользователь его не
   вводит.
3. **"Зарплата специалистов/руководителей для расчёта найма"** (Стажировки)
   должно ПОЛНОСТЬЮ совпадать с "Средняя зарплата специалиста" — это одно и то
   же значение, вводится один раз и переиспользуется в формулах (поле
   `v.specialistSalary`).
4. Правило распределения полей: поле становится вводимым, только если это
   настоящая переменная модели, которую пользователь называл явно в брифе.
   Все исследовательские/бенчмарочные коэффициенты (со ссылками на источники в
   комментариях Excel) остаются зашитыми константами и не выводятся как inputs.
5. Одинаковый показатель, встречающийся в Excel в нескольких местах, должен
   запрашиваться у пользователя один раз и переиспользоваться — не дублировать
   поля ввода.
6. У EVP и Кейс-чемпионатов — не выдумывать ROI/затраты, если их нет в Excel
   (EVP теперь ROI получил — см. п.7); у Кейс-чемпионатов ROI по-прежнему нет.
7. EVP был обновлён (второй Excel-файл, `2_Финансовая_выгода_updated_EVP.xlsx`):
   добавлены переменные поля `programCost` (стоимость проекта Changellenge >>)
   и `activationCost` (затраты компании на активацию EVP), добавлен расчёт ROI
   = (total - cost) / cost, продукт переименован в "EVP (активация)".

## Бренд (changellenge-brand skill, брендбук сентябрь 2025)

- Цвета: `#E71026` (красный, не более ~10% площади), `#121217` (почти чёрный,
  никогда чистый `#000000`), `#FFFFFF`, `#F1F1F1` (фон), `#DFE3E4` (серый),
  `#FFEAEC` (светло-красный акцент), `#6CB3CC` (бирюзовый), `#004F6B` (тёмно-синий).
- Шрифт: кастомный **Factor A** (начертания Black/Bold/Medium/Regular для
  цифровых материалов; Arial — только для PowerPoint).
  Файлы шрифтов — в `brand_assets/fonts/`.
  Встраивание в HTML — через `@font-face { src: url(data:font/ttf;base64,...) }`.
  Если нужно повторить: вставляйте base64 через отдельный Python-скрипт с
  плейсхолдером (например `__FONT_REGULAR__`) и `str.replace()` — не через
  Edit/Read напрямую, файл слишком большой.
- Логотипы/знаки — официальные SVG в `brand_assets/logos/` (red/black/white ×
  полный логотип/знак-шеврон). Обязательный элемент бренда — двойной шеврон «»».
- Радиус карточек — фирменная пропорция ~60 условных единиц у бренда,
  на вебе используется масштабированно (~28px).
- Навигация — капсульные "breadcrumb" пилюли.
- Если скилл `changellenge-brand` доступен в новой сессии — обязательно
  вызвать его заново (`Skill` tool) вместо использования копии SKILL.md здесь;
  копия в архиве — только для справки на случай, если скилл недоступен.

## Скрипты проверки (`scripts/`)

Локальная проверка расчётов через headless-браузер:
1. `python3 -m http.server 8791` в директории с `calculator.html`.
2. Playwright (`/opt/pw-browsers/chromium`) открывает страницу, вызывает
   `currentProduct.compute(values)` напрямую в контексте страницы.
3. Сравнивает результат с эталонными значениями, посчитанными вручную из
   Excel (через `openpyxl`, оба режима: `data_only=False` — сами формулы,
   `data_only=True` — закэшированные значения).
4. Делает полноэкранные скриншоты (десктоп 1400px и мобильная версия 390px)
   для визуальной проверки — примеры в `screenshots/`.

Файлы: `verify.py`, `verify2.py`, `verify3.py`, `verify_fix.py`,
`verify_evp.py`, `verify_home2.py` — каждый соответствует определённому этапу
правок (общая проверка, фикс округления EVP, фикс полей ввода, добавление
ROI в EVP, проверка главного экрана).

## UX-логика (кратко)

1. Экран выбора продукта (4 карточки).
2. Карточки-объяснения "почему возникает этот эффект" — коротко, для продажи
   идеи за 1-2 минуты.
3. Одноэкранная форма ввода: основные поля видны сразу, второстепенные —
   под "Настроить расчёт подробнее".
4. Пересчёт мгновенный, без кнопки — по любому изменению поля.
5. Крупные карточки результата: итоговый эффект, затраты, ROI.
6. Карточки "Из чего складывается эффект" — разбивка по компонентам.
7. Разворачиваемая панель "Как считается?" на каждый эффект: Логика /
   Использованные данные / Результат / Источник.
8. Кнопка "Вернуть исходные значения" — сброс к дефолтам.
9. RU-форматирование чисел везде (млн ₽, %, разряды тысяч), полная точность
   хранится во внутреннем состоянии.

Два уровня использования: Уровень 1 — продать идею за 1-2 минуты (общий
эффект + ROI), Уровень 2 — верификация для HRD/CFO (разворачивание "Как
считается?", проверка источников).

## Текущий статус / открытые вопросы

- Калькулятор полностью функционален, все 4 продукта верифицированы против
  Excel, бренд применён, все известные пользовательские правки внесены.
- **Не решено**: пользователь спрашивал "как сделать из этого лендинг?", в
  ответ было предложено опубликовать через Netlify Drop с помощью браузерной
  автоматизации ("Хотите, я сам это сделаю через браузер прямо сейчас и пришлю
  вам ссылку?"). Пользователь на это предложение не ответил (согласием или
  отказом) — переключился на другую задачу (обновление EVP), затем на запрос
  этого архива. **Не начинать публикацию через Netlify самостоятельно**, пока
  пользователь явно не подтвердит.
- Альтернативный/предпочтительный способ публикации в новой сессии — Cowork
  `Artifact` tool (публикация как hosted-страница на claude.ai), если он
  доступен в среде, где продолжится работа — это более стандартный путь, чем
  Netlify Drop.

## Как продолжить работу в новой сессии

1. Распакуйте архив, откройте `calculator.html` — это финальный рабочий файл.
2. Если нужны новые правки в математике — сверяйтесь с `source_files/*.xlsx`
   (открывать через `openpyxl`, смотреть колонки формул и комментариев).
3. Если нужны правки в бренде — по возможности используйте актуальный скилл
   `changellenge-brand`, если он подключён в новой среде; иначе — ассеты в
   `brand_assets/`.
4. Любые изменения формул — обязательно перепроверяйте скриптами из
   `scripts/` (адаптировав пути) против эталонных значений из таблицы выше.
5. Публикация: см. раздел "Текущий статус" выше.
